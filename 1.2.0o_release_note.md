# SwitchU fork 1.2.0o

With the Home toggle on Overlay, Breeze started over a game now comes up as
the overlay at once (interface 6).

Only the daemon changed in this release; the 1.2.0n menu works with it. The
new protocol message is between Breeze and the daemon only, so the menu never
sees it. Breeze needs a build that sends it: the first Breeze release after
beta127.02. With an older Breeze, or an older daemon, nothing changes.

## Overlay from the start

The daemon entered overlay mode only on the HOME press that left full-screen
Breeze. A fresh Breeze start over a running game (HOME with Breeze first, or
Breeze opened from hbmenu) therefore always came up full screen, over the
suspended game, even with the toggle on Overlay. It took HOME to the game and
HOME back to get the overlay.

Breeze now sends a new message, RequestOverlay, once its start-up work for the
game is done. The daemon then does what those two HOME presses did: it tells
Breeze to stop drawing to its applet window, brings the game to the front, and
shows Breeze over it. HOME then hides and shows the overlay as before.
`fork.txt` now reads `interface=6`.

Breeze waits for its start-up work on purpose. While it scans the game and
updates cheats it does not read the daemon's messages, and a command sent then
would time out, leaving Breeze and the daemon disagreeing about whether the
overlay is up.

Checked on the console (firmware 23.0.1, Atmosphere 1.12.1) with Well Dweller:
Breeze started by HOME went from full screen to the overlay in about a second
with no other press, and four HOME presses after that hid and showed it in
turn.

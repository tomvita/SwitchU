# SwitchU fork 1.2.0l

Games that read their launch parameter now start when they are launched from
sphaira, DBI, Breeze or hbmenu in applet mode.

Deploy the daemon and the menu together — `atmosphere/contents/…/exefs.nsp`
and `switch/SwitchU/bin/menu/main` are built as a pair. Only the daemon
changed in this release, so a 1.2.0b–1.2.0k menu also works with this daemon.

## Games that crashed when started from applet mode

A program running as an applet can only ask the system to start a game by
handing it a launch parameter, so an empty one goes along with every such
request. Most games never look at it. Some do: the Pixel Game Maker player
takes it as the path of the project to load, finds nothing there, and crashes
right after starting. Timothy and the Tower of Mu did this from sphaira, DBI
and Breeze in applet mode, and started fine from any of them in full memory
mode, where no parameter is sent.

The daemon now starts such a game without the parameter, the way it starts a
game from the SwitchU menu. A request made by the running game itself is left
as it is: a game that starts another of its own programs passes a real
parameter.

## One system service freed

The daemon opened the system's version-management service (`avm`) at boot and
never used it. That service has very few sessions, and holding one made other
homebrew fail to open it (sphaira's installer got error 0x615 on its last
step). The daemon no longer opens it.

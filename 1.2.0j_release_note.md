# SwitchU fork 1.2.0j

Games started from other programs now ask who's playing, as on Nintendo's
HOME. The menu's **Recent** sort now puts newly installed games first, and it
counts games started from sphaira, forwarders or Breeze.

Deploy the daemon and the menu together — `atmosphere/contents/…/exefs.nsp`
and `switch/SwitchU/bin/menu/main` are built as a pair. Nothing the two share
changed in this release, so a 1.2.0b–1.2.0i menu also works with this daemon.
It keeps its old Recent order, though. A 1.2.0j menu with an older daemon
shows Recent in title-id order.

## Who's playing

Since 1.2.0h, sphaira, hbmenu forwarders and Breeze can start games. Until now
the daemon picked the user silently: the last user chosen in the SwitchU menu,
otherwise the first one.

Now it decides the way the menu does before its own launches:

- A game that doesn't use accounts starts with none.
- A game where a user is optional starts as before.
- A game that needs a user starts with the menu's default profile if you set
  one in the settings. It also starts straight away when only one user
  qualifies. Otherwise Nintendo's own user picker appears. The default
  profile is skipped for games that need a Nintendo Account.

Cancelling the picker returns to HOME without starting the game.

## Recent

Nintendo's HOME orders games by the time the system last touched each one:
installing, updating and launching all move a game to the front. The daemon
now writes the game list in that order, and the menu's **Recent** sort follows
it.

- A freshly installed game comes first, instead of landing somewhere in the
  middle of the grid.
- A game started from sphaira, a forwarder or Breeze moves to the front, as
  one started from the menu does.
- Resuming a suspended game no longer changes the order.

The order the menu used to keep for itself is no longer used, so the first
Recent view after updating reflects the console's own history. **My order**
and **A-Z** are unchanged.

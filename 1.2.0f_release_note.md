# SwitchU fork 1.2.0f

A fix release over 1.2.0e. The Breeze interface level is unchanged (still 2),
so Breeze beta121.00 and newer are happy with either version and nobody is
forced to update; 1.2.0f is worth taking for the two crashes below.

Deploy the daemon and the menu together — `atmosphere/contents/…/exefs.nsp`
and `switch/SwitchU/bin/menu/main` are built as a pair.

## The menu could crash while starting

The menu restarts every time an applet closes, so this showed up as a crash on
the way back from a game, hbmenu or Breeze rather than at boot. It was
intermittent because it depended on how much memory was free at that moment.

Its 1x1 white texture was allocated without checking the result. That
allocation is refused when the image budget or the free-memory headroom check
says no, and the texture was then built from a null block, faulting in
`dkImageInitialize`. The white texture is now marked essential so neither soft
check can refuse it, a genuine failure is reported instead of crashing, and no
texture anywhere is built from an empty allocation.

## HOME with Quick Settings open froze the menu

Pressing HOME while the Quick Settings drawer was open left the menu with dead
buttons — B, the sticks and the shoulder buttons did nothing — while touch
still worked and the drawer could not be dismissed.

HOME with a suspended game resumes it, and resuming first captures the frame
that HOME returns to. That capture waits while an overlay is on screen, and
waiting for it switches off all button input; the drawer could then never be
closed, so the capture never finished. The capture now closes the drawer
instead of waiting for it.

A watchdog covers the same class of fault from any other cause: if button
input stays off for four seconds, the menu writes what is stuck to
`config/SwitchU/menu_focus.log` and lets go of the capture it was holding.

## Sleep and wake are now traced

Sleep and wake go to `config/SwitchU/power.log`, one line per event, written
and closed each time so it survives a hang and can be read over FTP while the
daemon runs (`daemon.log` is buffered and held open). Closing a held Breeze
for sleep is logged with it.

This is diagnostics, not a fix: a hang after a long sleep with Breeze held in
Overlay mode has been reported and is still unexplained. The log is what will
identify it.

Along with it, the daemon destroys any display layer a terminated Breeze left
behind, when the Breeze applet closes and at boot. In practice these layers
turn out to die with Breeze's own process, so this is a safety net.

## Log archives no longer overwrite each other

Rotated logs are named after the clock, which is not set yet at boot, so two
archives from the same boot took the same name and the earlier one was lost.
A counter is added when the name is already taken.

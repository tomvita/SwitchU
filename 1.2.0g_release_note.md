# SwitchU fork 1.2.0g

An interface release for Breeze's Break and Trace. The Breeze interface level
goes from 2 to 3: Breeze can now show itself over the running game on its own,
and the daemon tells it when it is about to be closed so a game stopped in the
debugger is never left stopped.

Nothing here changes what the menu does. Take it if you use Breeze's Break and
Trace; otherwise 1.2.0f behaves the same.

Deploy the daemon and the menu together — `atmosphere/contents/…/exefs.nsp`
and `switch/SwitchU/bin/menu/main` are built as a pair.

Mixed versions are fine in both directions. An older Breeze (beta121.01 and
before) works with this release exactly as it did with 1.2.0f, and a Breeze
built for this interface still works on an older fork — it simply waits for a
HOME press where it would otherwise come up by itself.

## Breeze can show and hide itself over the game

Breeze's overlay used to appear and disappear only on a HOME press, which the
daemon handles. Break and Trace needs it the other way round: when the game
stops at a breakpoint, Breeze has to come up by itself, and when the game is
let go it has to step back behind it.

Breeze now reports that with a new `StateChanged` message, so the daemon's idea
of the overlay stays true. That matters beyond the picture on screen: the next
HOME press, the sleep path and the input restore when the applet closes all act
on that state, and a wrong one would leave the game without a controller or
take two HOME presses to get anywhere.

## A held Breeze is told before it is closed

The daemon closes a held Breeze when the console goes to sleep and when the
game opens a library applet of its own. Until now it sent nothing unless Breeze
held the controller, in which case it asked it to hide.

With Break and Trace that is not enough: the game may be stopped at one of
Breeze's breakpoints, and once Breeze is gone nothing is left to let it run
again — the game would stay stopped through the sleep and after the wake. The
daemon now sends a `Release` message first, which gives Breeze the chance to
clear its breakpoints, let the game run, hand the controller back and drop its
display layer before it is closed.

## breeze_running carries more than one capability

`config/SwitchU/breeze_running` told the daemon that Breeze understands the
overlay protocol. It now holds space-separated capabilities and the daemon
matches whole words, so a Breeze that understands the two messages above can
say so (`overlay1 overlay2`) without breaking anything that only looks for
`overlay1` — which is exactly what an older daemon does, and why a new Breeze
still runs on 1.2.0f.
